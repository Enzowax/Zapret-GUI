# Проверка патча 2.44.0

Статус: финальный локальный релизный комплект. Коммит и публикация не выполнялись. Автоматические проверки не заменяют испытания драйвера, DNS, голосового Discord и Telegram на Windows.

## Область ревью Ponytail

Проверены приложение, core, компоненты измерений/управления/поиска, встроенный пакет tgproxy, пресеты и их подготовка, зависимости, сборка, CI, вспомогательные скрипты и тесты. Область — весь исходный проект, включая неизменённые файлы; сгенерированные build/release и двоичные файлы не рассматриваются как исходный код. Для навигации использован Graphify; UI дополнительно просмотрен напрямую, поскольку граф не индексирует .pyw полноценно.

Результат находится в PONYTAIL-REVIEW-2.44.0.md. Из 147 потенциально удаляемых строк 127 относятся к условному отказу от Linux fallback в upstream-коде; ещё 10 строк остаются в двух небольших упрощениях. Неиспользуемый запуск watchdog-автопоиска (10 строк) удалён в финальной версии. Удаляемых зависимостей не подтверждено. Совместимые обёртки измерений, отдельные стратегии с одинаковым UDP-блоком, проверки транзакций и отмены оставлены: их удаление противоречило бы требованиям патча.

## Заключительный проход

Дополнительно воспроизведены и исправлены:

- Ранний Стоп не отменял отложенный автозапуск и восстановление службы при открытии программы. Оба сценария теперь проверяются test_stop_cancels_pending_startup_actions.
- Отказ terminate ошибочно считался завершением, после чего терялась ссылка на живой процесс. Ошибка передаётся вызывающему коду, ссылка сохраняется (test_failed_stop_keeps_owned_process_reference).
- Отмена поиска заменяла прежнюю таблицу частичными результатами. Ошибка сохранения нового пула также успевала изменить настройки в памяти. Предыдущие результаты восстанавливаются в обоих случаях, память изменяется после успешной записи (test_unsuccessful_search_preserves_previous_visible_results).
- Отменённая серия после одного успешного замера считалась надёжной. Незавершённая серия больше не проходит (test_cancelled_measurement_is_not_reliable).
- Падение временного winws во время измерения не мешало пресету выиграть поиск. Состояние процесса проверяется и после измерения (test_trial_crashing_during_measurement_cannot_win_search).
- Пропадание интернета уже во время проверки кандидата загрязняло список неудачных стратегий. Подбор приостанавливается с возвратом исходной стратегии (test_network_loss_during_candidate_restores_original_without_blacklisting).
- Счётчик отказов снятого с проверки сервиса запускал лишнее восстановление. Счётчики ограничены текущими сервисами и сбрасываются при смене операции (test_removed_recovery_service_does_not_keep_failure_counter).
- Закрытие окна ожидало остановку процессов и блокировку управления прямо в Tk. Очистка перенесена в отдельный поток, окно закрывается после завершения; ошибка остановки показывается явно (test_quit_defers_process_cleanup_and_destroys_only_after_it_finishes).
- Архив перепроверяется по SHA-256 непосредственно перед распаковкой, из того же открытого файла. Без совпадающей суммы staging не создаётся (test_apply_update_requires_matching_digest_before_staging).
- Отчёты в корне предыдущего локального ZIP нарушали допустимую структуру самообновления. Теперь сборщик помещает их в _internal/release-notes.

В tests/test_windows_processes.py проверено реальное завершение принадлежащего приложению процесса, сохранение соседнего процесса и ветвь принудительного завершения после тайм-аута. Сгенерированный PowerShell-сценарий обновления действительно выполнен для временной установки: сохранены конфигурация, пользовательские пресеты и список; проверены копирование и ограниченная очистка staging. Только ожидание выхода pytest и запуск тестового EXE отключены. Это не испытание обновления живого работающего приложения.

Пользователь подтвердил, что доступен только основной компьютер. Поэтому проверка выполнена с обязательным снимком и откатом настроек. Реальная служба `zapret` успешно прошла цикл запуска с подтверждением состояния и штатной остановки. DoH Cloudflare был применён к четырём активным адаптерам и затем восстановлен из сохранённого снимка; конфигурация приложения вернулась к исходному состоянию. Во время этой проверки найдены и исправлены две ошибки нормализации GUID: один Windows возвращал GUID уже в фигурных скобках, а второй путь сравнивал GUID-объект со строкой. Отдельная команда аварийной остановки подтверждена при отсутствии процессов: после `taskkill` осталось 0 экземпляров `winws.exe`.

## Измерения интерфейса

Локальный микробенчмарк utils/benchmark_ui.py, тот же Python и компьютер. Это создание Tk-виджетов с отключёнными сетевыми и системными действиями; цифры не включают запуск процесса EXE, UAC, антивирус и проверки сети. Одно сравнение до/после; медиана используется только для пяти пар повторных переходов.

| Измерение | До | После |
| --- | ---: | ---: |
| Создание расширенного интерфейса | 1710 мс | 873 мс |
| Создание простого интерфейса | 571 мс | 562 мс |
| Перестроение расширенного интерфейса при смене темы, первый кадр | 1600 мс | 769 мс |
| Пара переходов между уже созданными страницами, расширенный режим | 22,0 мс | 22,5 мс |

Полные настройки теперь показывают первый кадр за 20 мс; достраивание заканчивается примерно за 474 мс. Раньше расширенные настройки создавались при запуске, поэтому их прежнее время открытия нельзя напрямую сравнивать с новым холодным открытием.

Обработка журнала занимает около 3 мс за порцию из 200 строк вместо блокирования примерно на 185 мс для всей очереди из 1000 строк. Это уменьшение длительности блокировки, а не сравнение одинакового объёма работы.

Сырые результаты: graphify-out/audit/ui-perf-before.json и ui-perf-final.json (локальные, исключены из Git).

## Пресеты, upstream и Windows

Все 22 исходных JSON-пресета сопоставлены по аргументам и порядку с BAT Flowseal zapret-discord-youtube 1.10.2; совпадение 22/22. Отчёт: graphify-out/audit/presets-parity.json. Исходные стратегии и winws не переписывались; пользовательские исключения добавляются при подготовке эффективных аргументов.

Из tg-ws-proxy v1.10.2 перенесена применимая обработка доменов в журнале. Локальная обработка 429 ограничена по времени и покрыта тестами. Версии и хеши записаны в upstream-versions.json.

Гипотеза о media-подключениях: четыре варианта знака DC проходят проверку расшифровки/признака media. Это проверяет локальную обработку флага, но не воспроизводит возможный сброс реального Telegram-соединения. Поэтому гипотеза не объявлена закрытой; необходим клиент и воспроизводимый сетевой сценарий.

Нативный предпросмотр успешно построил все страницы, проверил сохранение карточек после перестроения, простой светлый, расширенный светлый и тёмный режимы, размеры 920×620 и 1120×780. PowerShell Parser проверил три генерируемых DNS-скрипта без синтаксических ошибок; сами изменения DNS не выполнялись.

## Что остаётся перед публикацией

- Проверить ручной запуск из GUI, отмену и закрытие окна во время испытания, сворачивание и выход из сна.
- Проверить смену сети и выбранную политику восстановления с действительным частичным отказом сервисов.
- При появлении отдельного Windows-окружения воспроизвести отказ одного адаптера при DoH и проверить статический DNS отдельно от DHCP.
- Проверить обновление собранного приложения с сохранением пользовательской конфигурации, реальную доступность сайтов, голос Discord и Telegram/media отдельно.

До этих проверок релиз не следует публиковать как проверенный на реальных сетях. Код, архив, обновление, интерфейс и безопасные сценарии Windows завершили финальный локальный этап.
